# Руководство для агентов

## Назначение проекта

Интерактивная 3D-сцена на Three.js: шарики делятся при ударах о деревянные борта, заполняют арену, давлением выбивают одну доску и выкатываются наружу. Камера сопровождает отлетевшую доску, которая через баллистический полёт ударяется о камень и останавливается. Есть запись вертикального видео через `MediaRecorder`.

Проект использует vanilla JavaScript, ES-модули, Vite и Three.js. TypeScript, UI-фреймворк и внешний физический движок не используются.

## Команды

- `npm ci` — установить зависимости из lockfile.
- `npm run dev` — запустить Vite с доступом по `0.0.0.0`.
- `npm run build` — production-сборка в `dist/`.
- `npm run preview` — локально проверить production-сборку.

Автоматических тестов и отдельного линтера в проекте нет. Не добавляйте тестовый или линтер-скрипт в `package.json`, если это не запрошено отдельно.

## Структура

- `src/main.js` — запуск сцены, изменение размера, запись canvas в WebM 1080×1920 при 30 fps, состояние кнопки записи.
- `src/scene.js` — renderer, освещение, материалы, геометрия арены и досок, полёт доски, камень, столкновение доски с камнем, камера.
- `src/balls.js` — движение и столкновения шариков, деление, заполнение арены, давление и открытие пробитого борта.
- `src/style.css` — адаптивная раскладка страницы и элементы записи.
- `public/textures/` — текстуры дерева. Текстуры пола процедурно создаются в `scene.js`.
- `index.html` — русскоязычный интерфейс и canvas.

`dist/` и `node_modules/` игнорируются Git. Не редактируйте `dist/` вручную: каталог создаётся командой `npm run build`.

## Основной сценарий и инварианты

1. В начале есть один шарик. При ударе о борт он делится на два только если для обоих потомков достаточно места.
2. Столкновения шариков рассчитываются в плоскости XZ с фиксированным шагом 120 Гц. Скорость после столкновений сохраняется до выхода из арены.
3. При заполнении около 72% доступной площади неудачные попытки деления накапливают давление по сторонам. Четыре таких импульса на одной стороне выбивают среднюю доску соответствующего борта.
4. Допускается только один вылет доски за запуск. После него деление прекращается, выбранный борт открывается, шарики направляются наружу и постепенно тормозят снаружи.
5. Доска физически отсоединяется от группы бортов через `scene.attach(board)` и сохраняет исходную мировую позицию. Начальная скорость направлена наружу от пробитой стороны.
6. Камера начинает движение одновременно с отрывом доски. Не добавляйте паузу перед этим переходом: отрыв боковой доски должен оставаться видимым.
7. Во время полёта камера поднимается с 75° до 85° и отдаляется. При сближении с камнем фокус смещается между доской и камнем, чтобы оба объекта и полная длина доски помещались в кадре.
8. Камень находится на траектории на расстоянии 44 мировых единицы от исходной позиции доски. Полёт доски рассчитывается подшагами 90 Гц с гравитацией, вращением и контактом с землёй.
9. Столкновение использует `OBB` повёрнутой доски и сферический коллайдер камня. Удар неупругий: нормальная скорость удаляется, скорость и вращение сильно затухают; затем доска падает и останавливается у камня. Не заменяйте это проверкой только по центру доски или телепортацией к камню.
10. Область теней солнца следует за доской после вылета, поэтому при её изменении нужно сохранять видимость теней у камня.

Это специализированная физика сцены, а не универсальный rigid-body движок. Не описывайте её как полноценную общую симуляцию твёрдых тел.

## Где менять параметры

- `BALL_CONFIG` в `src/balls.js`: радиус, скорость, угол деления, cooldown.
- `PACKED_FILL_RATIO`, `PRESSURE_IMPACTS_TO_BREAK`, `OUTSIDE_FRICTION` в `src/balls.js`: момент пробития и торможение снаружи.
- `SCENE_CONFIG` в `src/scene.js`: формат кадра, размеры и начальная высота камеры.
- `ROCK_RADIUS`, `ROCK_DISTANCE`, `BOARD_PHYSICS_STEP` в `src/scene.js`: камень и точность полёта.
- `releaseBoard()` в `src/scene.js`: начальный импульс и вращение доски.
- `simulateBreakoutStep()` и `resolveRockCollision()` в `src/scene.js`: гравитация, земля и отклик на удар.
- `updateCamera()` в `src/scene.js`: длительность перехода, высота, zoom и кадрирование столкновения.

При текущих параметрах контрольная симуляция даёт пробитие примерно на 6,9 секунды и удар о камень примерно через 1,8 секунды полёта. Из-за столкновений небольшое изменение скорости может нелинейно менять тайминг и пробитую сторону; после таких изменений проверяйте весь сценарий заново.

## Проверка изменений

Минимум после изменения логики:

1. Выполнить `npm run build` и `git diff --check`.
2. Проверить физику шариков отдельно: `createBallSystem()` работает в Node с `new THREE.Scene()` и `environment: null`, без создания WebGLRenderer. Передайте `onBreakout`, задайте `courtDepth` по формуле из `createArenaScene()` и вызывайте `update(1 / 60)` в цикле.
3. Проверить сцену в браузере от начала до конца: деление, заполнение, один отрыв доски, выход шариков, движение камеры, полёт, контакт с камнем и остановку.
4. Убедиться, что боковая доска видна с первого момента отрыва, не проходит сквозь камень и не исчезает, а финальный кадр содержит доску и камень целиком.
5. Для записи проверить реальный `MediaRecorder`, размер 1080×1920 и сохранение WebM, если изменения затрагивают `main.js`, canvas или resize.

В фоновой вкладке `requestAnimationFrame` может быть сильно ограничен. Для визуальной проверки вкладка должна рендериться активно; замедленный браузерный тайминг не следует путать с ошибкой физического шага.

## Стиль работы

- Сохраняйте существующие названия и структуру модулей; код и комментарии в исходниках — на английском, интерфейс — на русском.
- Сохраняйте детерминированность: не вводите непредсказуемый `Math.random()` в последовательность сцены без необходимости.
- Не добавляйте зависимости для уже реализованной физики без явной необходимости.
- Не меняйте запись и визуальные материалы при задачах только о физике.
- После изменения описанного здесь поведения обновляйте этот `AGENTS.md`.
